# Changelog

All notable changes to this project are listed here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- The passkeys page can add fingerprint or face sign-in for the device in use. Before, a passkey could only be added from the offer after a password sign-in. Each new passkey is named after the platform of the device, such as Android or Windows.
- Sites open in their mobile version while a phone holds the screen. The bot's Chromium then sends the user agent of Chrome on Android and takes a drag as a touch, so it scrolls the page. A page that was already open fits the narrow screen too. The desktop version comes back on the next load after the phone gives the screen back.
- Bitwarden logins for the bot. The Bitwarden card in Connect apps takes the server address, the API key and the master password of the owner. They stay in the vault under a name that the model cannot read, and the server runs the official Bitwarden CLI itself. The new `browser_fill_login` tool types the user name, the password or the one-time code of a login into the focused field. The server reads the real page address, offers only the logins saved for that site, and asks the owner before it types. The bot never sees a value. The vault locks after ten idle minutes. The image installs `@bitwarden/cli` 2026.9.1. An integration script can no longer be given a secret that starts with `OAUTH_` or `BITWARDEN_`, and an app token cannot start with `BITWARDEN_`.
- The Connect apps catalog is a grid of cards sorted by name, with three columns on a phone. Each app shows its logo when it has one, drawn from shapes bundled with CloudBot. The other apps keep a colored initial.
- Gmail, Google Calendar, Google Drive, Google Docs and Google Sheets have their own cards in the Connect apps catalog. Connect opens Google's authorization page right away and asks only for that app's access. They connect through Google's own servers with one Google Cloud client that the admin sets once in the install `.env`, see `docs/GOOGLE.md`. On a hub, Google sends everyone back to the hub's main address, which passes the browser on to the right person. Without the client, the card says that Google is not set up yet.
- The Connect apps panel lists a catalog of 72 apps with category chips, such as Productivity, Code and Finance. Search also matches the description and the category.
- Connect apps signs in on the app's own page. Connect on Linear, Notion or a custom app opens the sign-in and approval page of the app, with no token to paste, and brings the owner back to CloudBot. The token goes to the vault and is renewed by itself. A server without that sign-in still asks for a token in the chat.

### Changed

- The bot asks for approval much less, like auto mode. The review that decides which tool calls need the owner now also runs on ChatGPT, after Claude and before Gemini. A message, a git push or a system change that the owner asked for in the chat runs without a card. Purchases and bookings still ask. When no provider can review, as on a bot that only uses opencode, the call runs instead of asking, and the blocked commands and the always-ask tools still hold.
- A bot with WhatsApp connected no longer refuses to answer on WhatsApp. When you ask, it sends or answers the message with WhatsApp Web in its browser. Messages from your number still arrive in the chat.
- The chat feels more alive while the bot works. The thinking bubble is now a status line under the last message, with the bot's small mascot looking around and a shine that sweeps the current step. It stays under a reply that is still streaming. A sent message slides up from the text box, and the mascot in the header shows a green dot while the bot works. Reduced motion turns the movement off.
- The image no longer carries gcc, g++ and scipy. matplotlib comes from pip wheels, so the image is smaller. The bot can install a compiler or scipy itself when asked.
- `sudo cloudbot update` removes build cache older than one day instead of three days, so the disk of a server that builds the image does not keep several GB of fresh cache.
- The CloudBot image is smaller. It keeps one copy of the Claude CLI and one OpenCode binary, and it drops the npm, uv and installer caches. The install guide says which `docker image ls` number to read for the image size.
- The chat header uses a bot profile pill and a More menu for model and provider settings. Assistant replies use full-width cards, and the composer has attachment and voice controls.
- The attachment menu offers file, photo and photo or video picker modes.

### Fixed

- A Codex bot sees the images attached to a message again. The image folder lost its setgid bit, so the files got the server's group and Codex could not read them. The review on ChatGPT also starts now, since it passed no setting to the Codex wrapper and sudo refused it.
- The back button of the phone no longer leaves the app. It closes the open panel, such as the bot list, the account, the bot profile, Connect apps or the Screen. From the chat on a phone it opens the bot list, and from the bot list it leaves the app.
- A long message in the text box no longer turns it into an oval that cuts the text at the corners. The box keeps its pill shape for one line and becomes a rounded box for more.
- A Codex bot follows its current instructions in an old chat. Codex kept the instructions a chat started with, so a changed rule, such as answering on WhatsApp, only reached new chats. Changed instructions now go into the chat before the next message.
- On Android, the message field and the expanded Screen panel stay above the navigation bar when CloudBot draws under it. Before, the bar covered the message field.
- The first key typed with the Keyboard button of the Screen panel no longer erases a character on the screen and adds a space.
- On a phone, the whole desktop fits in the Screen panel while you hold it. Before, the desktop stayed 500 pixels wide in a narrower panel, so its right side was cut off and could not be reached.
- The Screen panel shows the desktop again. The server closed every viewer right after it connected, because it did not know the fence, continuous updates and QEMU key messages that noVNC sends.
- The Screen panel on a phone no longer stays black. The server refused the resize request of the phone, because noVNC sends back the random screen id of TigerVNC, and the panel kept connecting again.
- A person stays signed in to the hub when CloudBot opens from its home screen icon, a notification or a link in another app. Hub sessions now end after 7 days, so each person signs in again once a week. Fingerprint or face sign-in on a device without a passkey says how to turn it on.
- On a phone, the Screen panel connects again on its own while the desktop starts, keeps the composer on screen and no longer opens the bot list on a sideways drag.
- The sign-in of an app opens in a new window. The CloudBot page stays where it is, and the new window tells it when the sign-in ends and closes itself.

### Changed

- While CloudBot starts, the bot shows as working. A message sent then gets an immediate note that CloudBot is starting, and it runs by itself when the start ends.
- The chat header shows only the model name for a provider that lists its models, such as GPT-6 Luna, and the bot no longer asks you to approve a model change.
- On a provider such as OpenCode, the bot no longer asks you to approve its own CloudBot tools twice, such as connecting a provider. The tool server already decides each call.
- When an AI provider renames its mode that asks before each tool, CloudBot uses the mode the agent lists instead of failing every turn with "could not switch to asking before each tool".
- OpenCode setup offers free models or an account API key for OpenCode Zen or Go. CloudBot checks the key, stores it in the vault and sends it through the local key proxy.
- The provider list calls the provider OpenCode, not "opencode free models".
- The bot knows how to change its provider and that a subscription, plan or account means the sign-in at a provider. CloudBot has no paid plan of its own.
- When you connect a provider in the chat, the bot of that chat runs on it from the next message, and the provider name in the header updates. Before, the bot kept the old provider.
- Picking a provider that needs no sign-in, such as OpenCode, no longer opens a blank browser tab.
- Grok signs in and takes an xAI key the way the xAI docs describe, and always runs with the Ask permission mode, so a saved always-approve setting no longer skips the review.
- A routine can repeat every minute. The shortest interval was 5 minutes.
- The buttons at the top of the bot list are in the order People, Search, New bot.
- The People button shows on every instance. On one that is not the owner's instance inside the hub, the panel is made of cards. A CloudBot that runs on its own says so and gives the install command with a copy button. A person's CloudBot tells them to ask the owner of the hub.
- Tool reviews now allow reads and harmless workspace work without an approval card, and ask before remote writes, system changes, outside-workspace deletion or overwrite, new app connections and changes to rules, limits or the active provider. A review denial stays a denial.
- A bot that hands a task or a reply to another bot of the owner no longer asks for approval each time. The review still asks when the hand-off carries something the owner did not ask for, and an owner rule can still deny it.
- An instance of a server for many people stays awake while a program that a person started listens on a port, such as a Node dev server in the workspace. It used to hibernate after five idle minutes, which stopped the server. It hibernates again after the program stops.
- Closing the browser window on the Screen panel no longer leaves a black screen. The browser comes back a second later on Google, and the empty desktop has the dark color of the app.
- The Screen panel is bigger. The picture takes about 80% of the width and the controls sit in a column on the right. One button hands the screen over or takes it back, one expands the panel to the whole window, and one closes it. The duplicate "I will keep it" button is gone.
- The bot's browser opens on Google instead of a blank page. A new tab opened after all tabs were closed does the same.

### Added

Routines and messages from webhooks, emails, page watches and other bots are skipped.

- The hub of a server with many people now runs as one piece. The sign-in page, the passkeys, the proxy for pages and WebSockets, and the idle shutdown all work together. The internal routes of the hub answer only to the other containers, never to a public address. A person that was deactivated cannot sign in with a passkey.
- A people panel for the owner of a server with many people. A button next to the search and the new bot button opens it in the chat area. The owner adds a person by name, deactivates or reactivates them, resets a password, or deletes them after typing the name. A new password is shown once and is not kept.
- An idle shutdown for the people of a server. After five minutes without a request or an open connection, the hub asks the instance if it is busy. A running turn, routine, page watch, webhook, messaging connection, email account or setup conversation keeps it awake. An idle instance stops and starts again when its person comes back. Set `CLOUDBOT_IDLE_MINUTES` on the hub to change the five minutes.
- Passkey sign-in for the people of a server. A person who signs in with a password on a phone is offered a fingerprint or face sign-in, and can skip it for 180 days. A person has up to ten passkeys and can remove them on a page of their own address. The passkey is bound to the address of that person, so it works only there.
- The owner can ask a bot to manage the people of the server. A bot lists people, adds one by name, deactivates or reactivates them, and resets a password. The owner approves a card before an add, a deactivate or a reset. The sign-in address and the one time password go to the owner in a notice in the chat. The model never sees the password, and it is not stored in the chat history or the logs.
- The hub for many people on one server. It runs each person in a container of their own with a private network and four volumes. It keeps the total memory of the running instances under a budget and starts one on demand. The owner instance asks the hub to add, deactivate, reactivate, reset and delete people. A new person gets a one time password. `node dist/hub/main.js reset-password <name>` prints a new one.
- The front door of a server with many people. Each person signs in with a name and a password at an address of their own, such as `maria.example.com`. A new password must be changed at the first sign-in. After five failed tries a name or an address waits 15 minutes. The hub starts the instance of the person when they arrive and shows a "Starting your environment" page until it is ready. Then it passes every request and WebSocket to that instance. A person reaches only their own instance.
- Install a server for many people with one command. Compose runs the hub, a restricted Docker socket proxy and Caddy with automatic certificates for every person's address. The installer takes the domain, checks its DNS, prints the first password of the owner and keeps the memory budget in `.env`. `cloudbot update` rebuilds the shared image and `cloudbot reset-password <name>` prints a new password.
- Run a task once at a set time. Ask a bot for a reminder in two hours, and it makes a routine that runs one time and then turns itself off. A time that has passed is refused.
- Sign in with a passkey. Ask a bot in the chat to add one, tap the card, and this phone or computer can sign in from the new sign-in screen. The bot lists them and posts a card to remove one. The setup link from the server still works.
- Import pasted instructions or attached plain text, Markdown and common JSON assistant exports. The owner approves the full profile and memory draft in chat. Platform tools, skills, files, credentials, approval settings and routines are not imported.
- The mascot hops from its bot row into the latest message when the owner opens a chat. The 780 ms animation leaves the layout in place, keeps text clear and skips reduced motion or layouts where the list and chat are not side by side.
- Each bot runs on the AI provider the owner picks: Claude, ChatGPT (Codex), Gemini, GitHub Copilot, Cursor, Grok, Mistral, Qwen, Kimi or the free opencode models. The setup chat asks which provider to use, then whether to use a subscription or an API key. A provider with only one way skips that question. Ask a bot to switch and its next message starts a new conversation on the new provider. Ask it to connect another provider and the list comes back in the setup chat.
- A subscription sign-in runs the provider CLI's own login. The chat shows its link and device code, or a code field when the provider's page shows a code to paste back. The web page opens the sign-in page in a new tab. A code the provider refuses ends the sign-in with a message and the provider list comes back. CloudBot never sees the credentials.
- An API key for OpenAI, Gemini, xAI, Mistral, Qwen (Alibaba Cloud Model Studio) or Kimi (Moonshot AI) goes through the secure form. CloudBot checks it with one request to the provider, keeps it in the vault and sends it through a local key proxy, so the bot only sees a dummy key. An xAI key runs on Grok Build through its `xai.api_key` ACP method.
- Providers other than Claude and ChatGPT run over the Agent Client Protocol. Every tool the CLI asks to run goes through the same review as a Claude tool, and a call that names a CLI's sign-in or config folder is refused. The Docker image installs every CLI at a pinned version where possible, owned by root, and starts them through a fixed wrapper.
- A Gemini subscription runs on the Antigravity CLI (agy), since Google moved Gemini subscriptions there. A hook sends each tool call agy wants to run to the same review as a Claude call. Ask the bot for a Gemini model such as gemini-3.8-flash, and the effort picks its low, medium or high level. A Gemini API key still runs on the Gemini CLI.
- A template gallery in a public GitHub repository, mateuscmtropical/cloudbot-templates by default. The bot lists its templates with gallery_list, which reads one index file and shows each name, title, description and blocked tools. Set CLOUDBOT_GALLERY_REPO to read another repository.
- gallery_install makes a bot from a gallery template. The owner sees the whole template on the approval card first, and the same checks as an import apply. The card works for ten minutes and for one install.
- gallery_share opens a pull request to the gallery from a fork of it in the bot owner's GitHub account. It needs GitHub connected for the bot, and the owner approves the exact file first. The card says when the file replaces an existing one.

### Changed

- The chat header shows only the model name for a provider that lists its models, such as GPT-6 Luna, and the bot no longer asks you to approve a model change.
- When the review of a tool call fails, the approval card shows the tool and its whole input, or says the input is too long to show.
- Yellow is no longer a bot color. Its dark shade read as brown, so bots and channel posts that had it are now orange. New bots and the mascot tool never pick yellow. A stored color the app does not know shows as blue instead of breaking the mascot.
- Buttons light up when the pointer is over them, including the choice buttons on the setup card. A disabled button does not. The change shows with reduced motion on, and the keyboard focus ring is unchanged.
- Turns run the official claude CLI directly. The Claude Agent SDK is no longer used.
- After the owner denies an action, the same action is refused at once if the bot tries it again in that turn, so no second approval card appears. The bot is told not to retry it.
- A streamed reply stays smooth in a long chat. Stored messages no longer render again on every new word, and the words that arrive within one screen frame are drawn together. On a phone class CPU with 200 messages on screen, a fast reply went from about 11 to about 49 frames per second.
- Mascots that are off screen stop following the pointer and stop blinking, so a long chat does no work for them.
- The mascot's eyes move much further toward the pointer and the caret, and the whole cloud leans a little the same way, so the look reads on a small mascot too. Under reduced motion the eyes and the lean still move, without the glide.
- New messages, the streamed reply and panels move in with short transform and opacity animations, and the bot list slides over more softly on a phone. Buttons give a little when pressed. Reduced motion turns these off.
- The server lets the browser keep the built web app files, whose names change with each build, for a year. The page itself is checked on every visit, so a new version still shows at once. A repeat visit no longer downloads the app again.

### Added

- A new hub no longer prints a generated owner password. The first person who opens the owner address chooses a password and becomes the owner. After that the page closes and only the owner adds people.
- A CloudBot inside a hub has an Account button in the sidebar. It opens a panel to change the password, manage passkeys and sign out. A person can change the password at any time with the current one.
- The name form of the hub address accepts a capitalized name and shows a wrong name on the same screen. It also works in Chrome and Opera, where the page policy blocked the redirect to the person.
- Teach a task by recording the screen. Ask a bot to learn a task from you, do it once on its screen, and give the screen back. The bot turns the recorded steps into a skill for you to approve. Password and other secret fields are recorded only as a secret step, never with their value.
- Skills. Ask a bot to learn a skill, or give it a link, and it saves the steps after you approve the whole text on a card. The bot reads a skill before a task it covers, and lists or removes its skills when asked.
- Talk to a bot from Telegram. The owner saves a Telegram bot token through the secure form and sends a one-time code from the chat to the Telegram bot. Only that Telegram account can then talk to the bot, in a private chat, and the replies to its messages come back there. Text only for now.
- When a turn that started on Telegram waits for an approval or for you on the screen, Telegram gets one line that says to open the web app. The card itself stays in the web app.
- A bot can connect its own mailbox with owner-provided IMAP and SMTP settings. The password goes from a secure chat form into the vault. New mail arrives as an outside-data task, with delivery ids persisted across restarts. Every outgoing email waits for owner approval of all recipients, the subject and the full text. Attachments are not supported.
- Receive text instructions from the owner's WhatsApp number through Meta's official WhatsApp Business Cloud API. The bot sets it up in the chat with secure forms. Replies stay in the web app, and existing push notices arrive when notifications are enabled. CloudBot never sends a WhatsApp message.
- The message box has a microphone button in browsers with speech recognition, such as Chrome and Edge. The spoken words are added to the text in the box. The browser's speech service turns the audio into text, and the app never receives the audio.
- The web app installs on a phone or computer as an app, with the cloud mascot as its icon. It has a web app manifest and a small service worker that caches nothing.
- Push notifications. Ask a bot in the chat to turn them on, and it posts a card with a button. The browser asks for permission only after you tap the button. A notification comes when a turn finishes, when an approval waits and when the bot hands over its screen. It shows the bot's name and a short neutral line, never the text of a message. Tapping it opens that bot and message. A tab that already shows the bot gets a silent one that closes at once. A bot sends at most one "finished" notification a minute, and none for a webhook. Ask the bot to turn them off and it posts a card that removes this browser. Browsers use their own push services (Google, Mozilla, Apple or Windows), and CloudBot sends only to those. The push key is made once in the data folder and never leaves the server.
- The bot refuses to send a payment card number, a Brazilian CPF or a US Social Security number outside the chat. The check covers browser typing, hand-offs to other bots, integration runs, outside connector tools, web fetches and searches, watches, bots and routines, some shell commands that send data, GitHub writes and shared text files. The bot is told to ask for the number in the secure form.
- Card, CPF and Social Security numbers in the bot's replies are masked in the chat, and only the last four digits stay readable.
- The bot's system prompt and review prompt cover health and personal finance details, and page text that asks the bot to send data elsewhere. The bot tells the owner when a page asks for that.
- A bot sets up a morning brief and quiet check-ins when you ask in the chat. A brief is a daily routine. A check-in is a routine with `isQuiet` set. ### Security

- A local run listens on `127.0.0.1` only, so it is not open to the network. Set `HOST` to listen elsewhere. The Docker image sets `HOST=0.0.0.0`. The start log prints the address the server really listens on.
- A request that changes state under `/api` must come from the page itself. The `Origin` must be the server's own host or the host of `CLOUDBOT_PUBLIC_URL`, and a request with no `Origin` needs `Sec-Fetch-Site: same-origin`. Another site or another local port can no longer send it with the owner's cookie. A script that calls the API without a browser must now send an `Origin` header.
- A request with a body must be `application/json`, or `multipart/form-data` on the upload route. Other types get a 415.
- Every response sends a Content Security Policy that allows only the app's own files, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy: no-referrer` and same-origin opener and resource policies. Images from other sites, such as in bot replies, no longer load.
- The setup link and the start log use the address the server really listens on, `127.0.0.1` by default, and not `localhost`.
- The Codex engine gives each bot a `CODEX_HOME` and a separate `HOME` beside it, both mode 0700, so `~` cannot reach the Codex config or sign-in. A command or file change that names the Codex home or a `.codex/` folder is declined without a review. File-change paths are resolved through symlinks, and a path that cannot be resolved is declined. Shell commands do not get `CODEX_HOME`. The check is a floor, not a parser: a path the command builds at run time, for example from `HOME` beside the Codex home, still reaches the review.
- The Codex engine also serves the bot's own tools through the loopback server. Codex reads the token from `CLOUDBOT_TOOLS_TOKEN`, never from its command line, and `shell_environment_policy.exclude` keeps the token out of every shell command. Each tool call is reviewed like a Claude tool call, and an allowed call runs once.

- Telegram no longer sends the same message to the bot twice after a restart. The poll resumes from the saved update offset, and a disconnect forgets it.
- The bot's mascot shows only beside its latest message, so it no longer stays on an earlier reply above the owner's message.
- A background process that a command started in its own session no longer keeps running after the turn ends. Each turn marks its processes, and the marked ones are ended when it is over.
- The plus in the new bot and attach buttons sits exactly in the center of the round button.
- `share_file` works on Windows and macOS. The file must stay inside the workspace, and the opened file must be the one the path leads to, checked by file identity. Linux uses the same check. On Windows the open does not refuse links, so the realpath and identity check are the guard there.
- The buttons inside the Rules panel had no background and their text could not be read.
- The header buttons are one group now. On windows up to 1200px wide they sit in a row after the bot name instead of covering it, and on a phone they take a second row.
- `browser_click` checks the focus after a click. A click on a field that did not take the focus is repeated once, and the result tells the model whether a field has the focus.
